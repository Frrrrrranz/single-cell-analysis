## 一、复盘：为什么会出现错误？

### 错误清单回顾

| # | 错误 | 严重程度 | 发现来源 |
|---|------|---------|---------|
| 1 | `resolution=0.8` 而非论文的 `0.4` | P0（必须改） | 同学评审 |
| 2 | DE 方法 `t-test` 而非论文 Wilcoxon | P0（必须改） | 同学评审 |
| 3 | `LIGAND_GENES` 命名误导（实为 ECM marker） | P1（建议改） | 同学评审 |
| 4 | analyze.py vs scRNA_py.ipynb 参数不一致 | P0（必须改） | 自身交叉检查 |
| 5 | 缺失配体-受体互作分析（核心内容缺失） | P0（功能缺失） | 同学评审 |
| 6 | DE 固定取 top 50 基因，无显著性过滤 | P1（建议改） | 自身审查 |

### 根因分析（5 Why）

**Why 1：`resolution=0.8` 而不是 `0.4`？**
- → 直接原因：开发时凭经验选择了默认值 0.8，没有查阅论文 Methods 部分
- → 根本原因：代码编写前没有创建「论文参数 vs 实现参数」对照表

**Why 2：DE 方法用了 `t-test` 而不是 `wilcoxon`？**
- → 直接原因：认为 t-test 是"快速且适合"（见代码注释第437行）
- → 根本原因：对单细胞数据分布特性判断失误，且未与论文方法对齐
- → 深层原因：**用"我觉得"替代了"论文说"**

**Why 3：`LIGAND_GENES` 命名误导？**
- → 直接原因：变量命名时思维跳跃，把 ECM 蛋白和"配体"混为一谈
- → 根本原因：**变量名反映了分析者的意图而非实际内容**，代码阅读者（包括未来的自己）会被误导

**Why 4：脚本和笔记本不一致？**
- → 直接原因：两个文件由不同思路编写（analyze.py 是完整流程，notebook 是测试探索）
- → 根本原因：**缺少单一事实来源**，没有统一参数配置文件

**Why 5：核心缺失（配体-受体互作）？**
- → 直接原因：认为做到"细胞注释"就算完成了复现
- → 根本原因：**未完整理解论文目标**——论文的核心是配体预测，细胞注释只是前序工作

### 根因总结

| 根因类别 | 具体问题 | 解决方案 |
|---------|---------|---------|
| 📄 **文献分析不系统** | 未逐段提取 Methods 参数 | 在 Plan 阶段就创建参数对照表 |
| 🧠 **经验主义** | 用个人假设替代论文原文 | 所有非论文参数必须声明 reason |
| 🏷️ **命名不严谨** | 变量名与实际内容不匹配 | 命名前确认语义后再编码 |
| 🗂️ **多重实现失控** | 脚本 vs notebook 两套代码 | 统一参数源，单一事实来源 |
| 🎯 **目标理解偏差** | 只做了"细胞分类"而非"配体预测" | Plan 阶段先确认论文核心 Figure 目标 |

## 二、复查工作流（使用规范）

**在开始任何 scRNA-seq 分析相关的实施前，请遵循以下 6 步工作流：**

### 步骤 0：论文解剖 🔍

```markdown
## [论文名] 参数提取表
| 分析步骤 | 论文参数（原文引用） | 原文出处（章节/页码） |
|---------|-------------------|-------------------|
| 归一化 | XXX | Methods p.X |
| 聚类分辨率 | XXX | Methods p.X |
| ... | ... | ... |
```

**强制要求：** 将论文 Methods 部分的每一个可量化参数提取到表中。
**验收标准：** 表格中不应出现空单元格（论文未明确时注明"未给出"）。

---

### 步骤 1：创建参数对照表 📐

将所有参数的四种状态标记清楚：

```
[✅] = 严格一致（必须标注原文引用）
[⚠️] = 不同但合理（必须写 Reason）
[❌] = 明确偏离（必须改）
[❓] = 论文未明确（标注"未给出"，写明你的选择+Reason）
```

**关键问自己：** 这个参数是来自论文，还是来自我的习惯/工具的默认值？

---

### 步骤 2：语义命名验证 🏷️

对每个变量/函数名，问：

1. 这个名字**精确**描述了变量内容吗？
2. 如果别人（或三个月后的我）看到这个名字，会不会误解？
3. 名字中是否包含了**不存在的假设**？（如把 ECM marker 叫成 ligand）

**禁止的命名模式：**
- 用上位概念命名下位内容（如 `LIGAND_GENES` 装 ECM 蛋白）
- 模糊的缩写（如 `temp_data`, `res`）
- 与内容相反的方向词

---

### 步骤 3：交叉一致性检查 🔄

如果存在多个实现文件（脚本 + 笔记本），必须：

1. 创建一个共享参数配置文件（如 YAML/JSON/Toml）
2. **所有文件从同一配置源读取参数**
3. 运行参数打印命令验证一致性

```python
# 建议：在脚本和 notebook 开头统一打印参数
print(f"resolution = {RESOLUTION}")
print(f"de_method = {DE_METHOD}")
print(f"mt_threshold = {MT_PCT}")
```

---

### 步骤 4：论文核心目标对齐 🎯

问这三个问题：

| 问题 | 回答后判定 |
|------|-----------|
| 论文的 **Figure X** 是核心发现？ | 分析必须至少覆盖对应 Figure 的 80% 内容 |
| 分析做到哪一步才算"完成复现"？ | 明确 stopping criterion |
| 当前分析覆盖了论文前百分之几的内容？ | < 60% → 需要补充分析模块 |

**教训：** 本次分析只做了 Figure 1（细胞注释），但论文核心是 Figure 5-7（配体-受体互作）。

---

### 步骤 5：同行复查触发 ⏰

在以下节点**必须**暂停并请求复查：

| 触发节点 | 复查内容 |
|---------|---------|
| Plan 阶段完成参数对照表后 | 检查参数是否与论文对齐 |
| 初步结果生成后 | 检查结果是否合理、与论文 Figure 趋势一致 |
| 最终报告前 | 完整通读，检查命名、逻辑、覆盖度 |

---

### 步骤 6：复查清单（Checklist）

在提交任何分析计划/代码前，逐项检查：

```markdown
## scRNA-seq 分析复查清单

### 参数对齐
- [ ] 已创建论文-实现参数对照表
- [ ] 所有 ⚠️ 参数都有书面 Reason
- [ ] 所有 ❌ 参数已被修正
- [ ] 无"默认值依赖"——每个参数都有意识选择

### 命名规范
- [ ] 无变量命名误导（如 LIGAND_GENES 问题）
- [ ] 变量名精确描述内容
- [ ] 命名风格统一（参考 .clinerules 命名规范）

### 代码一致性
- [ ] 多个实现文件共享同一参数源
- [ ] 脚本/notebook 参数打印后一致
- [ ] 无两个文件矛盾（如 resolution=0.8 vs 0.1）

### 论文覆盖度
- [ ] 明确列出了论文的核心 Figure 列表
- [ ] 分析覆盖了核心 Figure 对应的方法
- [ ] 知道分析做到了论文的百分之几

### 统计学严谨性
- [ ] DE 方法适合单细胞数据分布
- [ ] 多重检验校正被正确应用
- [ ] 阈值设置不是"固定值"而是数据驱动

### 可复现性
- [ ] 所有随机种子已固定（random_state=42）
- [ ] 结果可以重新运行得到一致结果
- [ ] 中间结果有保存点

### 文档完整性
- [ ] 参数选择有注释说明为什么
- [ ] 变量名没有误导性缩写
- [ ] 报告说明了与论文的差异点
```
