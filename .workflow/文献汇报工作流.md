# 📋 文献汇报工作流（Literature Review Workflow）

> **用途：** 标准化文献汇报 HTML 的创作流程，从 PDF 提取图片到撰写 HTML 的完整指南。
> **版本：** v1.0 | **创建日期：** 2026-05-28
> **基于案例：** ENEURO.0066-20.2020 / PNAS.117.9466.2020 / COMMUN-BIOL.5.1105.2022

---

## 一、概述

### 1.1 工作流目的

规范文献汇报的创作流程，确保每次输出的 HTML 汇报在**格式、内容、质量**上保持一致。

### 1.2 输入与输出

| | 内容 |
|---|------|
| **输入** | PDF 原文 + Gemini 提供的小图标注信息与位置 |
| **输出** | 标准文献文件夹（含 HTML 汇报 + figures + 补充材料） |

### 1.3 整体流程

```
📥 Step 1：接收与准备
   ↓
🖼️ Step 2：提取 Figure 图片
   ↓
🔍 Step 3：文献内容核对（对照原文 + Gemini 标注）
   ↓
✍️ Step 4：撰写 HTML 汇报
   ↓
🔍 Step 5：HTML 内容自查
   ↓
📎 Step 6：补充材料（可选）
   ↓
✅ Step 7：最终检查清单
```

---

## 二、Step 1：接收与准备

### 2.1 接收内容

用户提供：
1. **PDF 原文**（如 `ENEURO.0066-20.2020.full.pdf`）
2. **Gemini 小图标注信息**（包含每张 Figure 的小图编号、内容描述、位置信息）

### 2.2 创建文献文件夹

**命名规范：** 使用文献 ID（期刊缩写 + 卷号 + 页码）

```
📁 ENEURO.0066-20.2020.full/       ← 文献文件夹
├── 📄 ENEURO.0066-20.2020.full.pdf       ← PDF 原文
├── 📄 ENEURO.0066-20.2020.full-ony-translated.pdf  ← 翻译版（如有）
├── 📁 paper_figures/                     ← Figure 图片
│   ├── page_02.png
│   ├── page_03.png
│   ├── ...
│   └── figure_index_clean.txt            ← 图序索引
├── 📄 文献标题（中文）.html              ← HTML 汇报（主文件）
└── 📄 补充材料（可选）.html              ← 补充说明（如有）
```

---

## 三、Step 2：提取 Figure 图片

### 3.1 使用 Python 脚本提取

从 PDF 中提取所有图片，保存到 `paper_figures/` 目录。

**脚本位置：** 附录 B 提供了可直接使用的 Python 脚本。

### 3.2 图片命名规范

```
page_02.png    ← PDF 第2页的图片
page_03.png    ← PDF 第3页的图片
...
```

> **注意：** PDF 中的图片页码可能与论文中的 Figure 编号不一致。需要对照 Gemini 标注信息确认每张图片对应哪个 Figure。

### 3.3 创建图序索引

在 `paper_figures/` 中创建 `figure_index_clean.txt`，记录每张图片对应的 Figure 编号：

```
page_02.png → Figure 1 (PDF第2页)
page_03.png → Figure 1 (PDF第3页，Figure 1续)
page_04.png → Figure 2 (PDF第4页)
page_05.png → Figure 3 (PDF第5页)
...
```

## 四、Step 3：文献内容核对 🔍

> **参考：** `.workflow/scRNA-review-checklist.md` 的「步骤 0：论文解剖」和「步骤 1：参数对照表」

这是**最容易出错**的环节，必须逐项核对。参考 `PNAS.117.9466.2020.full/纠错.md` 中的教训。

### 3.1 论文解剖——提取 Methods 参数

创建参数对照表，逐段提取 Methods 中的可量化参数：

```markdown
## [论文名] 参数提取表
| 分析步骤 | 论文参数（原文引用） | 原文出处 | 实现值 | 状态 |
|---------|-------------------|---------|-------|------|
| 测序平台 | XXX | Methods | XXX | [✅/⚠️/❌/❓] |
| 标准化方法 | XXX | Methods | XXX | [✅/⚠️/❌/❓] |
| 聚类分辨率 | XXX | Methods | XXX | [✅/⚠️/❌/❓] |
| ... | ... | ... | ... | ... |
```

**状态标记：**
- `[✅]` = 严格一致（标注原文引用）
- `[⚠️]` = 不同但合理（必须写 Reason）
- `[❌]` = 明确偏离（必须改）
- `[❓]` = 论文未明确（标注"未给出"，写明选择 + Reason）

### 3.2 Figure 信息核对（对照原文 + Gemini 标注）

逐图确认以下信息，**这是纠错的重点环节**：

| 核对项 | 说明 | 常见错误（来自纠错.md） |
|--------|------|----------------------|
| **图表类型** | UMAP / t-SNE / 热图 / 气泡图 / 小提琴图 / 火山图 / 堆叠柱状图 / 饼图 / 组织切片 / 网络图 | 热图 ↔ 气泡图 混淆；饼图 ↔ 堆叠柱状图 混淆 |
| **小图编号** | A/B/C/D/E... 确认数量与顺序 | 遗漏小图（如漏掉 Figure 1E）；编号顺序错误 |
| **标志基因** | 基因名拼写、大小写 | 基因名写错（如 Sfrp4 写成 Sfrp）；张冠李戴 |
| **细胞类型命名** | 使用原文术语，禁止自创 | 自创 MP1/MP2（原文为 MC/MP） |
| **数据来源** | 自行培养 / 公共数据库 / 已发表数据 | 混淆不同神经元的数据来源层级 |

### 3.3 核心目标对齐

参考 `.workflow/scRNA-review-checklist.md` 步骤 4，问三个问题：

| 问题 | 回答后判定 |
|------|-----------|
| 论文的 **Figure X** 是核心发现？ | HTML 必须至少覆盖对应 Figure 的 80% 内容 |
| 分析做到哪一步才算"完成"？ | 明确 stopping criterion |
| 当前 HTML 覆盖了论文百分之几的内容？ | < 60% → 需要补充内容 |

## 五、Step 4：撰写 HTML 汇报

### 4.1 HTML 模板

使用附录 A 提供的完整 HTML 模板。模板包含：

- **CSS 样式体系**：横版幻灯片、打印优化、统一配色
- **标准幻灯片顺序**：10 页标准结构
- **Figure 页布局**：左图右文

### 4.2 标准幻灯片顺序

| 页码 | 内容 | 说明 |
|------|------|------|
| 1 | **封面** | 文献标题（中英文）、期刊信息、关键词 |
| 2 | **研究背景** | 研究问题、传统认知、研究空白、研究策略 |
| 3 | **技术路线** | 流程图 + 实验样本设计 + 数据分析流程 |
| 4 | **实验基本原理** | 关键技术原理详解（scRNA-seq、Harmony、CSC-MS 等） |
| 5-N | **Figure 逐页解析** | 每页一个 Figure，左图右文布局 |
| N+1 | **细胞类型鉴定** | 表格展示所有细胞类型及其标志基因 |
| N+2 | **细胞间通讯分析工具** | 工具介绍（CellPhoneDB / SingleCellSignalR 等） |
| N+3 | **关键通讯通路** | 核心 LR 通路总结 |
| N+4 | **结论与展望** | 核心发现 + 临床意义 |
| 最后 | **参考文献** | 论文引用 |

### 4.3 Figure 页规范

每个 Figure 独占一页，采用**左图右文**布局：

```
┌─────────────────────────────────────────────────┐
│  Figure X: [标题]                                │
├──────────────────────┬──────────────────────────┤
│                      │  fig-caption: 图注        │
│   图片区 (58%)       ├──────────────────────────┤
│                      │  fig-subnote: 小图说明    │
│   img src="..."      │  A: ...                  │
│                      │  B: ...                  │
│                      │  C: ...                  │
│                      ├──────────────────────────┤
│                      │  关键要点列表             │
│                      ├──────────────────────────┤
│                      │  fig-note: 核心结论       │
└──────────────────────┴──────────────────────────┘
```

**小图说明（fig-subnote）规范：**

```html
<div class="fig-subnote" style="margin:8px 0; padding:8px 10px; background:#f5f5f5; border-radius:8px; font-size:0.9em;">
  <strong>小图说明：</strong>
  <ul style="margin:2px 0 2px 14px;">
    <li><strong>A：</strong>[图表类型 + 内容描述]</li>
    <li><strong>B：</strong>[图表类型 + 内容描述]</li>
    <li><strong>C：</strong>[图表类型 + 内容描述]</li>
    <!-- 依此类推 -->
  </ul>
  <p style="margin:4px 0 0 0; font-size:11px; color:#d93025;"><strong>→ 关键结论：</strong>[一句话总结]</p>
</div>
```

### 4.4 样式组件使用规范

| 组件 | CSS 类 | 用途 |
|------|--------|------|
| 技术标签 | `tool-badge` / `tool-badge-red/blue/green/orange/purple` | 标记技术/工具名称 |
| 关键框 | `key-box` | 突出核心发现 |
| 高亮 | `highlight` | 强调关键术语 |
| 红色高亮 | `highlight-red` | 强调重要警示 |
| 流程图 | `flow-row` + `arrow` | 技术路线流程 |
| 双列布局 | `two-col` | 对比展示 |
| 结论卡片 | `conclusion-card` | 总结性内容 |

### 4.5 纠错标记规范

- 对不确定的内容使用 HTML 注释标记：`<!-- NOTE: 待确认 -->`
- 对原文未明确的内容标注：`<span style="color:#e37400;">[论文未明确]</span>`
- 对 Gemini 标注与原文不一致处，优先以原文为准并记录

## 六、Step 5：HTML 内容自查 🔍

> **参考：** `.workflow/scRNA-review-checklist.md` 的「步骤 6：复查清单」

### 5.1 Figure 信息复查（逐图对照原文）

```
- [ ] 图表类型描述正确（UMAP vs t-SNE vs 热图 vs 气泡图 vs 组织切片）
- [ ] 小图编号与原文一致（无遗漏、无多余）
- [ ] 标志基因名称拼写正确（大小写、数字）
- [ ] 细胞类型命名使用原文术语（禁止自创）
- [ ] 图片路径正确（paper_figures/xxx.png）
- [ ] 图片能正常显示（src 路径无误）
```

### 5.2 内容准确性复查

```
- [ ] 技术原理描述准确
- [ ] 数据来源和样本信息正确
- [ ] 引用数据有原文支撑
- [ ] 无自创概念/命名（如 MP1/MP2 这类错误）
- [ ] 参数值（分辨率、阈值等）与原文一致
```

### 5.3 格式规范复查

```
- [ ] 幻灯片顺序符合标准模板
- [ ] CSS 样式统一（无遗漏样式类）
- [ ] 打印优化完整（@media print）
- [ ] 所有 tool-badge 颜色正确
- [ ] 所有 key-box 突出核心发现
- [ ] 参考文献格式正确
- [ ] HTML 无语法错误（标签闭合）
```

### 5.4 常见错误类型（来自纠错.md 经验）

| 错误类型 | 示例 | 预防措施 |
|---------|------|---------|
| 图表类型误判 | 热图 ↔ 气泡图；饼图 ↔ 堆叠柱状图 | 对照原文 Figure Legend 逐字确认 |
| 小图张冠李戴 | Figure 2 的 UMAP 描述 → 实际是组织切片 | 对照 Gemini 标注 + 原文 Figure Legend |
| 基因名错误 | Sfrp4 拼写错误；基因名大小写不规范 | 从原文复制粘贴，不手动输入 |
| 细胞命名错误 | 自创 MP1/MP2（原文为 MC/MP） | 使用原文术语，禁止发明新名称 |
| 遗漏小图 | 漏掉 Figure 1E 的描述 | 逐图核对小图编号 A/B/C/D/E... |

### 附录 B：PDF 图片提取脚本

将以下脚本保存为 `extract_pdf_figures.py`，放在根目录使用：

```python
"""
PDF 图片提取脚本
用法：python extract_pdf_figures.py <PDF路径> <输出目录>
示例：python extract_pdf_figures.py "ENEURO.0066-20.2020.full/ENEURO.0066-20.2020.full.pdf" "ENEURO.0066-20.2020.full/paper_figures"
"""

import sys
import os
from pathlib import Path

try:
    import fitz  # PyMuPDF
except ImportError:
    print("请先安装 PyMuPDF: pip install PyMuPDF")
    sys.exit(1)

def extract_figures(pdf_path, output_dir):
    """从 PDF 中提取所有图片"""
    pdf_path = Path(pdf_path)
    output_dir = Path(output_dir)
    output_dir.mkdir(parents=True, exist_ok=True)
    
    doc = fitz.open(pdf_path)
    total_images = 0
    
    for page_num in range(len(doc)):
        page = doc[page_num]
        images = page.get_images(full=True)
        
        for img_idx, img in enumerate(images):
            xref = img[0]
            base_image = doc.extract_image(xref)
            image_bytes = base_image["image"]
            image_ext = base_image["ext"]
            
            # 命名：page_页码_序号.扩展名（通常取第一个大图）
            filename = f"page_{page_num + 1:02d}.{image_ext}"
            filepath = output_dir / filename
            
            with open(filepath, "wb") as f:
                f.write(image_bytes)
            
            total_images += 1
            print(f"  [提取] 第{page_num + 1}页 → {filename}")
    
    doc.close()
    print(f"\n✅ 完成！共提取 {total_images} 张图片到 {output_dir}")
    
    # 创建图序索引文件
    index_path = output_dir / "figure_index_clean.txt"
    with open(index_path, "w", encoding="utf-8") as f:
        f.write("# Figure 图序索引\n")
        f.write("# 请对照 PDF 和 Gemini 标注信息，填写每张图片对应的 Figure 编号\n\n")
        for page_num in range(len(doc)):
            f.write(f"page_{page_num + 1:02d}.png → Figure ? (PDF第{page_num + 1}页)\n")
    
    print(f"📄 图序索引已创建：{index_path}")
    print("⚠️  请对照原文和 Gemini 标注，手动更新 figure_index_clean.txt 中的 Figure 编号")

if __name__ == "__main__":
    if len(sys.argv) < 3:
        print("用法：python extract_pdf_figures.py <PDF路径> <输出目录>")
        sys.exit(1)
    
    pdf_path = sys.argv[1]
    output_dir = sys.argv[2]
    
    if not os.path.exists(pdf_path):
        print(f"❌ PDF 文件不存在：{pdf_path}")
        sys.exit(1)
    
    extract_figures(pdf_path, output_dir)
```
